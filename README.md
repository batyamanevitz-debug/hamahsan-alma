מימוש פיקסל-פרפקט ורספונסיבי של עיצוב הפיגמה `עיצוב אתר סחר`
(רוחב עיצוב 1920px):

* **דף הבית** — node `631:2441` → [`index.html`](index.html)
* **דף מוצר** — node `577:24` → [`product.html`](product.html)
  (מקושר מכרטיס המוצר *Perfumes De Marly* ומעיגול המותג בדף הבית)
* **דף תשלום** — node `577:771` → [`checkout.html`](checkout.html)
  (מקושר מכפתור *קנה עכשיו* בדף המוצר)
* **דפי קטגוריה** — node `577:1952`, תבנית אחת ב־[`category.html`](category.html)
  לפי `?cat=`. ארבע קטגוריות ראשיות (בשמי נשים כברירת מחדל, `perfume`,
  `makeup`, `hair`) ו‑15 תתי קטגוריות שמגיעות מהתפריטים הנפתחים —
  `brands`, `unisex`, `men`, `luxury`, `sets`, `kids`, `best`,
  `beauty-brands`, `cosmetics`, `body`, `face`, `hair-brands`,
  `devices`, `styling`, `haircare`.
* **תפריטים נפתחים** בהדר — nodes `679:138` (בשמים), `679:286` (איפור),
  `679:277` (הכל לשיער). קיימים בכל הדפים.
* **פאנל חיפוש** — node `593:327`. נפתח מאייקון הזכוכית המגדלת בהדר,
  בכל הדפים.
* **סל קניות (מגירה)** — node `582:103`. נפתח מכפתורי "הוספה לסל"
  (דף מוצר, סרגל דביק, כרטיסי הקטגוריה) ומאייקון העגלה בהדר. קיים בכל הדפים.
* **חלוניות הסינון והמיון** בדף הקטגוריה — nodes `618:135` (מותג),
  `619:510` (מחיר), `618:254` (דירוג), `619:484` (מרכיב),
  `619:427` (סגנון הניחוח), `619:458` (צורך), `619:571` (מיון לפי).

## הרצה

## לוח ניהול

[`admin.html`](admin.html) — ניהול מלא של החנות מהדפדפן, בעברית ורספונסיבי.
שש לשוניות: מוצרים, קטגוריות ומותגים, דפי תוכן, בלוג, הגדרות חנות והזמנות.

### כניסה

מסך הכניסה מבקש **סיסמה בלבד**. המייל של חשבון המנהל קבוע בקוד
(`ADMIN_EMAIL` ב-[`js/admin.js`](js/admin.js)) והסיסמה נבדקת מול Supabase Auth.

להוספת מנהל נוסף:

1. ליצור משתמש ב-Supabase: **Authentication → Users → Add user** (עם Auto Confirm User).
2. בעורך ה-SQL: `select public.grant_admin('המייל@שלו.com');`
3. לעדכן את `ADMIN_EMAIL` אם רוצים שהוא יהיה החשבון שנכנס מהמסך הזה.

חשוב: משתמש מחובר **אינו** מנהל. רק מי שרשום בטבלת `admins` יכול לשנות
משהו — כל פוליסת כתיבה בדאטהבייס דורשת `public.is_admin()`. לכן העובדה
ש-`admin.html` נגיש לכולם ב-GitHub Pages אינה חושפת את החנות: מי שיפתח
אותו בלי הסיסמה יראה מסך התחברות ולא יוכל לקרוא הזמנות או לשנות דבר.

הסיסמה היא ההגנה היחידה על נתוני הלקוחות בטבלת `orders`. Supabase דורש
לפחות 6 תווים, וכדאי הרבה יותר.

## דאטהבייס (Supabase)

הפרויקט הוא `touuyegybctmfdtzlbmt` (region ap-southeast-2). הטבלאות:

| טבלה | תפקיד |
|---|---|
| `products` | הקטלוג. `sort_order` קובע את סדר ההצגה. |
| `categories` | עץ הקטגוריות. `parent_id` ריק = קטגוריה ראשית. ה-`slug` הוא המפתח ב-`category.html?cat=` |
| `brands` | מותגים ולוגואים |
| `pages` | דפי תוכן סטטיים |
| `blog_posts` | מאמרי הבלוג |
| `site_settings` | מפתח/ערך: באנרים, כותרות ופרטי קשר |
| `orders` | הזמנות. `items` ו-`shipping_address` הם JSON |
| `admins` | מי רשאי לנהל את החנות |

ב-`products` השדות `brand` ו-`cat` הם עותקים לתצוגה שמסונכרנים אוטומטית
מ-`brand_id` ומ-`category_id` על ידי טריגר, כדי שהחנות תוכל לשלוף שורה
שטוחה אחת בלי join.

* **קריאה** — האתר פונה ל-REST של Supabase עם מפתח ציבורי (`sb_publishable_...`).
  המפתח נמצא ב-`js/store.js` בכוונה: RLS על הטבלה מתיר `select` בלבד,
  ולכן אי אפשר להוסיף, לשנות או למחוק מוצרים איתו.
* **כתיבה** — רק מהדשבורד של Supabase או עם service key. אין לאתר הרשאת כתיבה.
* **עריכה** — לשנות מחיר או שם בטבלה, לרענן את הדף, וזהו. אין צורך בקומיט.
* **סדר** — לשנות `sort_order` כדי להזיז מוצר קדימה או אחורה ברשת.

### שלוש שכבות של גיבוי

פרויקט Supabase חינמי נכנס להשהיה אחרי כשבוע בלי שימוש, ולכן `js/store.js`
לא סומך על הדאטהבייס בלבד:

1. **Supabase** — המקור הרגיל.
2. **עותק שמור** ב-localStorage (`alma.catalog.v1`) — אם הרשת נכשלת או שהתשובה
   מאחרת יותר מ-5 שניות.
3. **הקטלוג המוטמע** ב-`store.js` — אם גם עותק שמור אין. האתר תמיד מציג מוצרים.

`Store.source` מדווח מאיפה הגיע הקטלוג בפועל (`supabase` / `cache` / `fallback`),
ו-`Store.ready` הוא ה-promise שדפי הקטגוריה והמוצר ממתינים לו לפני שהם מציירים.

## הערות

* המרווחים והגדלים בדסקטופ נלקחו ישירות מהפיגמה (רוחב תוכן 1280px,
  כותרות 40px/55, כרטיס מוצר 296.25px, קלף המלצה 405×237 וכו').
* סדר הפריטים בשורות (תפריט, קטגוריות, מוצרים, מותגים, פוטר) מותאם
  לסדר הפיזי שבעיצוב — חלק מהשורות מסודרות LTR למרות שהאתר RTL,
  בדיוק כמו בקובץ המקור.
* אייקון האינסטגרם ברצועת הסושיאל יוצא ריק מהפיגמה, ולכן שוחזר כ‑SVG
  זהה בגודל ובצבע.
* כותרת המאמר הראשי בבלוג מוצגת במלואה
  ("מהפכת ה‑K‑Beauty בישראל…"), בעוד שבפיגמה היא חתוכה בקצה המסגרת.
* בדף המוצר: סרגל ה"הוספה לסל" הדביק מופיע אחרי גלילה מעבר לכפתורי
  הרכישה ונעלם מעל הפוטר (בפיגמה הוא מצויר כשכבה סטטית).
* הטאבים "למי זה מתאים" ו"למה תתאהבי בו" מקבלים טקסט קצר משלהם —
  בפיגמה עוצב רק תוכן הטאב "על המוצר".
* התפריטים הנפתחים: בדסקטופ נפתחים ב‑hover ובלחיצה (וגם מקלדת),
  ונסגרים ב‑Esc / לחיצה בחוץ. במובייל הם נפתחים כאקורדיון בתוך תפריט
  ההמבורגר, בלי התמונה. לתפריט "הכל לשיער" אין תמונה גם בפיגמה,
  ולכן הפאנל שלו ברוחב התוכן בלבד.
* בדף הקטגוריה: רשת המוצרים זורמת LTR (כמו בפיגמה — המחירים יורדים
  משמאל לימין), בעוד שתוכן הכרטיסים עצמם RTL.
* חלוניות הסינון נפתחות בלחיצה ונסגרות ב‑Esc / לחיצה בחוץ, והן מסננות
  וממיינות את הרשת בפועל. במסכים צרים החלונית נצמדת אוטומטית פנימה
  כדי לא לגלוש מהמסך.
* פאנל החיפוש נפתח מתחת להדר בגובה 119px, עם קו תחתון לשדה, אייקון
  חיפוש בימין וכפתור סגירה מעליו, ומציג תוצאות חיות מהקטלוג.
* סל הקניות נפתח כמגירה מצד שמאל (שם נמצא אייקון העגלה) עם שכבת כהות
  מאחוריו, ותוכנו נטען מהמצב השמור — כך שהוא זהה בכל הדפים וגם אחרי רענון.
* בדף התשלום: יש ולידציה, קופונים ומסך אישור הזמנה — אבל אין שליחה
  לשרת ואין סליקה אמיתית.
  שם המוצר בסיכום ההזמנה מופיע בשחור (בפיגמה הוא לבן על רקע לבן,
  כלומר בלתי נראה).
